# slide-review

研究発表のスライドをレビューするスキル。

## 何をするか

スライドを **3つのレイヤー**に分けて、上から順にレビューする。

| # | レイヤー | 見るもの | 観点の定義 |
|---|---|---|---|
| 1 | 全体の論理構成 | ストーリー（骨格・流れ・現在位置）、論理の飛躍、過不足・配分 | [references/layer1-structure.md](references/layer1-structure.md) |
| 2 | ページ内構成 | 何をどれだけ載せるか、箇条書き、図・表・数式による説明、言葉づかい | [references/layer2-page.md](references/layer2-page.md) |
| 3 | デザイン | レイアウト、文字、色、図解、一貫性、アニメーション、誤字、約物 | [references/layer3-design.md](references/layer3-design.md) |

**必ず 1 → 2 → 3 の順で行う。** 上位レイヤーの指摘が下位を無効化するため。構成ごと消えるページのフォントサイズを指摘しても意味がない。

対象は**日本語の研究発表スライド**（ゼミ・中間発表・学会発表など）。英語のスライドと、発表者の所作・準備プロセスは対象外。

観点は次の2つの資料をもとにしている。doc 内では出典を区別せず統合してある。

- 研究室のスライド方針（3レイヤーの定義そのもの）
- 「スライドデザインのススメ ver1.3.1」山本直輝（早稲田大学 基幹理工学部 情報理工学科）

## 優先順位

**レイヤー番号が小さいほど優先。** 修正コストが 1 > 2 > 3 の順に大きく、かつ上位の修正は下位の修正を作り直させるため。レイヤー1の `should` は、レイヤー2の `must` より先に着手する。

順位付けのキー: **レイヤー番号 → 重要度（`must` / `should`）→ 影響ページ数**。ただし `nits` はレイヤーを問わず最後。

この結果、次の2つが起きる:

- レイヤー1で削除・移動・分割・統合を提案したページは、そのページに対するレイヤー2・3の指摘が `保留` にまとめられ、件数だけ示される。消えるかもしれないページの文言を先に直させないため
- レイヤー1に `must` が残っているうちは、レイヤー3の詳細が省略され、レイヤー1の対応後に再度かけるよう促される

指摘には**ページ番号**と**重要度**が付き、最後に「次にやること」が着手順で3つ出る。ここだけ読めば動ける。

## 評価の考え方

**`references/` の項目は合格条件ではない。** 見落としを防ぐための探索リストであって、全て満たす必要はないし、点数も付けない。デザインに100点満点の答えはなく、目指すのは60〜80点。

観点より上位に立つ規範が3つある。

1. **接続性が最優先** — ある観点を満たすことで前後のページとのつながりが悪くなるなら、その観点は適用しない。指摘を出さない
2. **帰結を言えない指摘は出さない** — 「観点Xに反する」は理由にならない。「どのページで聴衆がどう詰まるか」を言えるものだけが指摘になる
3. **単ページ最適化をしない** — レイヤー2・3の修正案がレイヤー1の流れを壊すなら出さない

網羅した長いリストより、直せば確実に良くなる数件のほうが資料は良くなる。件数の上限は設けていないが、規範2で絞られる。

## 使い方

導入方法はリポジトリ直下の [README](../README.md) を参照。

多くのエージェントでは `/slide-review` で呼べる。スラッシュコマンドに対応していない場合は「slide-review を使ってレビューして」と頼めばよい。会話の中で「このスライド見て」「発表資料のレビューして」と言うだけで起動することもある。

### 特定のレイヤーだけ

```
slide-review structure   # レイヤー1のみ（1 でも可）
slide-review page        # レイヤー2のみ（2 でも可）
slide-review design      # レイヤー3のみ（3 でも可）
```

構成が固まった後にデザインだけ見たい、といったときに使う。

### 渡す形式

精度の高い順:

1. **Marp / Slidev / reveal.js などの Markdown ソース** — 一番良い。ファイルパスを渡すだけ
2. **PDF** — レイヤー3まで判定できる
3. **画像** — そのまま貼れる
4. **PowerPoint / Keynote** — PDF に書き出してから渡す。テキスト抽出だけだとデザインが評価できない

画像や PDF を読めないエージェントではレイヤー3は判定できない。その場合はレイヤー1・2 のみ実施され、その旨が明示される。

レビュー前に、発表の場・持ち時間・聴衆の前提知識を聞かれることがある。先に伝えておくと1往復減る。

## 観点を編集する

各レイヤーの観点は `references/` の3ファイルにある。ここを直せば挙動が変わる。`instructions.md`（手順・出力形式）を触る必要はない。

内容は上記2つの方針資料から起こしてある。運用しながら追記・調整していく。

編集するときの注意:

- **レイヤーの境界を守る。** ページの並び順はレイヤー1、ページの中身はレイヤー2、見た目はレイヤー3。迷ったら各ファイル末尾の「このレイヤーで出す指摘の例」を見る
- **箇条書きで、1項目1観点。** チェックボックス記法（`- [ ]`）は使わない。「全部埋めるもの」に見えると、観点の充足そのものが目的化する
- **特定のエージェントに依存する書き方をしない。** ツール名や独自機能に触れると他のエージェントで動かなくなる
- 編集は次のセッションから即反映される。`install.py` を再実行する必要はない
